# PRD: 닌자거북의홈 — 모여봐 앱마을

## 목표

게시판 링크 하나로 인디 앱 10개를 소개하고, 방문자가 3초 안에 필요한 앱의
플랫폼·최소 OS·버전·다운로드·신고·법적 링크를 찾게 한다. 미출시 앱도 숨기지
않고 곧 출시될 잎으로 보여준다.

## 사용자

- 주 유입: 커뮤니티/게시판의 모바일 브라우저
- 핵심 행동: 앱 잎을 열어 정보 확인 → 다운로드 또는 GitHub 신고
- 보조 행동: 이름·동물·기기를 이 브라우저에만 저장하는 선택적 입주
- 개인정보 기대: 계정·이메일·서버 가입 없이 둘러보기

## 정보 구조

| 영역 | 역할 |
| --- | --- |
| Mac 나무 | macOS 앱 4개 |
| iPhone 나무 | iOS/Android 앱 6개 |
| 지면 잎 | 흔들기 후 발견한 앱의 빠른 목록 |
| 집 | 주민 개인화 상태를 로컬로 표시 |
| 우편함 | 미출시 앱 안내 |
| 그루터기 | 퇴역 제주택배비지원 표시 |
| 마을 게시판 | TMT와 관리자 편집 |

## 기능 요구사항

### F-001 앱 카탈로그

`shipping.yml`에서 생성한 레지스트리를 사용해 10개 앱을 모두 렌더링한다.
각 상세에는 이름(한/영), 한 줄 설명, 플랫폼, 최소 OS, 버전, 다운로드 링크,
GitHub 신고 링크, privacy, support를 레지스트리 값 그대로 표시한다.

### F-002 잎 상호작용

잎은 버튼으로 상세 모달을 열 수 있다. 나무 흔들기는 released 상태의 아직
떨어지지 않은 잎 하나를 지면으로 보내며, unreleased 잎은 유지한다. `다시
매달기`는 원래 숲으로 되돌린다. 모션을 꺼도 모든 잎은 처음부터 보인다.

### F-003 주민

입주 신청은 선택 사항이다. 이름·동물·주 사용 기기를 받아
`appvillage.resident`로컬 키에만 저장하며 이메일 필드, 계정, 네트워크 전송은
없다. 저장 성공 시 선택한 기기에 맞는 잎 하나를 선물로 지면에 보여준다.

### F-004 게시판과 관리자

`data/tmt.json`의 정규화된 항목을 게시판에 표시한다. 관리자 편집은 기존
`/api/tmt` 인증/PUT 흐름을 유지하고 공개 홈에는 편집 버튼만 제공한다.

### F-005 법적 페이지와 신고

앱별 shipping URL을 사이트맵에 자동 포함한다. 신고는 GitHub Issue Form 하나로
통일하며 이메일 신고 경로를 만들지 않는다. 법적 페이지에 법률상 필요한
연락처만 예외로 유지한다.

## 비기능 요구사항

- 정적 공개 라우트, 런타임 외부 요청 0
- OKLCH 토큰, self-hosted `public/village` 자산, `next/font`
- 모바일 우선, 320px 이상 가로 스크롤 없음
- 키보드 접근, 적절한 landmark와 modal semantics
- `prefers-reduced-motion`에서 정보와 CTA를 그대로 제공
- `npm run lint`, `npm run build`, `npm run test` 통과

## 제외

로그인, 이메일 수집, CMS, 검색, 댓글, 다크 모드 토글, 외부 analytics, PWA,
스토어 제출과 GitHub Release 공개는 이 제품 사이트 범위에 포함하지 않는다.
